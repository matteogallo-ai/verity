# Claims

Every capability listed in [`features.md`](features.md), the code that implements it, and the tests that
prove it. `scripts/check_claims.py` (CI job `claims`) parses the table below and fails
when a `shipped` claim has no test, a listed test does not exist or does not pass, or
its Features / Roadmap sections disagree with a claim's status.

A claim is `shipped` only if every listed test passes. `roadmap` means not
implemented or not tested; `features.md` lists it under Roadmap, never under Features.
Tests under `web/` are vitest files: `check_claims` checks that they exist, and the
CI `web` job runs them.

| C01 | Every citation quote is a verbatim substring of its source document; citations that are not are dropped. The search treats the apostrophes `' ’ ‘ ʼ` as one character and the double quotes `" “ ” « »` as another; the stored quote is the document's own text. The space on either side of any of these double quote marks is optional, in every language, so `« oui »` cited as `"oui"` or `«oui»` is found, and `said "yes` as `said"yes`; between two words a gap is still required. The gap between a number and its French ordinal suffix is optional too, because a PDF's superscript suffix extracts detached: `1 er` cited as `1er`, `3ème` as `3 ème`; only a whole suffix joins its number, so `2 e-mail` is not found as `2e-mail`. Editing a corpus file replaces its chunks and deleting it removes them, in both stores, so a quote is never validated against text the document no longer has.
